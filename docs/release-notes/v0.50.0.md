# v0.50.0

**Release Date:** 2026-02-15
**Breaking Changes:** Yes

## Summary

Replace generated interceptor classes with pre-compiled arity-based generic types. Instead of generating 4 types per method member (interceptor class + 3 inner classes), each method now uses a single field declaration of a pre-compiled library type. This eliminates thousands of generated types from consumer projects, targeting significant MSBuild build time improvement.

## What's New

### Pre-compiled Arity-Based Interceptor Types

All method interceptors are now pre-compiled generic types in the KnockOff library, parameterized by arity (parameter count):

- `MethodInterceptor0<TReturn>` through `MethodInterceptor8<T1,...,T8,TReturn>` (sync non-void)
- `VoidMethodInterceptor0` through `VoidMethodInterceptor8<T1,...,T8>` (sync void)
- `AsyncMethodInterceptor0<TReturn>` through `AsyncMethodInterceptor8<T1,...,T8,TReturn>` (async non-void)
- `AsyncVoidMethodInterceptor0` through `AsyncVoidMethodInterceptor8<T1,...,T8>` (async void)

Property and indexer interceptors are now concrete types with delegate-based fallbacks:

- `PropertyGetInterceptor<TValue>`, `PropertyGetSetInterceptor<TValue>`
- `IndexerGetSetInterceptor<TKey, TValue>`

### Generated Code Reduction

| Metric | Before (v0.49.0) | After (v0.50.0) |
|---|---|---|
| Generated types per non-overloaded method | 4 | 0 |
| Generated types per overloaded method group | 9-12 | 1 (thin compositor) |
| Generated types per property | 1 | 0 |
| Generated types per indexer | 1 | 0 |

### Build Time Improvement

| Branch | Run 1 | Run 2 | Run 3 | Average |
|---|---|---|---|---|
| v0.49.0 (baseline) | 29.1s | 28.7s | 27.8s | **28.5s** |
| v0.50.0 (pre-compiled) | 14.3s | 12.6s | 13.4s | **13.4s** |

**~53% reduction in clean build time** for the full solution (KnockOff library + generator + all test projects). The bottleneck was the number of generated types the C# compiler must process, not lines of code.

### Fallback Mode

Methods with ref/out parameters, ref returns, or >8 parameters continue using the previous generated-class approach. Events are unchanged.

## Breaking Changes

### `LastArgs` Named Tuple Fields

`tracking.LastArgs.fieldName` no longer works -- named tuple fields become unnamed (`Item1`, `Item2`, etc.). Tuple destructuring continues to work:

```csharp
// Before (v0.49.0):
tracking.LastArgs.name    // named field access

// After (v0.50.0):
tracking.LastArgs.Item1   // unnamed field access
var (name, value) = tracking.LastArgs;  // destructuring still works
```

### Async Void Methods: `.Return()` to `.Call()`

Methods returning `Task` or `ValueTask` (void async) now use `.Call()` instead of `.Return()`:

```csharp
// Before (v0.49.0):
stub.SaveAsync.Return((data) => savedData = data);

// After (v0.50.0):
stub.SaveAsync.Call((data) => savedData = data);
```

### Generated Interceptor Type Names

Explicit references to generated interceptor class names (e.g., `AddInterceptor`) will break. The interceptor is now `MethodInterceptor2<int, int, int>`. Most user code uses `var` or accesses interceptors inline and is unaffected.
