# v10.33.0 - Verifiable Support for User-Defined Methods

**Release Date:** 2026-02-01
**NuGet:** [KnockOff 10.33.0](https://nuget.org/packages/KnockOff/10.33.0)

## Overview

User-defined methods in stand-alone stubs now properly support `.Verifiable()` and participate in `Stub.Verify()` aggregation.

## New Features

### Verifiable User-Defined Methods

Previously, calling `.Verifiable()` on a user-defined method interceptor did nothing—the state wasn't tracked and aggregate verification ignored these methods.

Now user-defined methods work like regular interface methods:

```csharp
public partial class MyStub : IMyInterface
{
    // User-defined method with custom implementation
    public int Calculate(int x) => x * 2;
}

// Mark as verifiable
stub.Calculate.Verifiable();

// Use the stub
var result = stub.Calculate(5);

// Aggregate verification includes user methods
stub.Verify();  // Passes - Calculate was called
```

**With call count expectations:**
```csharp
stub.Calculate.Verifiable(Times.Exactly(2));
stub.Calculate(1);
stub.Calculate(2);
stub.Verify();  // Passes - called exactly twice
```

**Note:** User-defined methods are intentionally excluded from `VerifyAll()`. Since user methods always have an implementation (the user provides it), they are always "configured." Only methods explicitly marked with `.Verifiable()` are included in `Stub.Verify()`.

## Bug Fixes

### Guard Condition Expansion

Fixed an issue where stubs with only user-defined methods (and no regular interface methods) would not generate `Verify()`/`VerifyAll()` methods at all. The guard condition now correctly checks for all verifiable member types.

## Technical Notes

- Added `_isVerifiable` and `_verifiableTimes` fields to user method interceptors
- Added `CheckVerification()` method for Stub.Verify() aggregation
- Expanded guard condition in FlatRenderer to include user methods and properties
- 18 new tests covering user method verification scenarios
