# v0.51.0

**Release Date:** 2026-02-16
**Breaking Changes:** Yes

## Summary

Replace 36 arity-based interceptor types with 4 TTuple generic types (`MethodInterceptor<TDelegate, TArgs, TReturn>` and variants). Named ValueTuple fields restore `LastArgs.fieldName` access (reversing the v0.50.0 breaking change). TSyncDelegate type parameter enables natural lambda parameters on async simplified callbacks.

## What's New

### TTuple Interceptor Types

The 36 arity-based types (`MethodInterceptor0` through `MethodInterceptor8`, times 4 families) are replaced by 4 TTuple types:

- `MethodInterceptor<TDelegate, TArgs, TReturn>` (sync non-void)
- `VoidMethodInterceptor<TDelegate, TArgs>` (sync void)
- `AsyncMethodInterceptor<TSyncDelegate, TDelegate, TArgs, TReturn>` (async non-void)
- `AsyncVoidMethodInterceptor<TSyncDelegate, TDelegate, TArgs>` (async void)

`TArgs` is a named ValueTuple (e.g., `(string name, int value)`), so IntelliSense shows parameter names on `LastArgs`, `When()`, and callback lambdas.

### LastArgs Named Fields Restored

`tracking.LastArgs.fieldName` works again, reversing the v0.50.0 regression:

```csharp
// v0.50.0 (broken):
tracking.LastArgs.Item1

// v0.51.0 (restored):
tracking.LastArgs.name
```

### TSyncDelegate for Async Callbacks

Async interceptors now carry a `TSyncDelegate` type parameter, enabling natural lambda parameters on simplified sync callbacks:

```csharp
// Before (v0.50.0) - args as tuple:
stub.SaveAsync.Call((args) => savedData = args.data);

// After (v0.51.0) - natural params:
stub.SaveAsync.Call((data) => savedData = data);
```

This applies to `.Call()`, `.Return()`, `.ThenCall()`, and `.ThenReturn()` on async interceptors.

### Ref/Out Overload Dispatch Fix

Fixed a generator bug where explicit interface implementation dispatch passed ref/out arguments as a tuple instead of individual parameters with ref/out modifiers. Overload groups containing ref/out members now work correctly.

## Breaking Changes

### When() Tuple Syntax for 2+ Parameters

For methods with 2+ parameters, `When()` now requires tuple syntax (double parentheses). This is because `TArgs` is a ValueTuple, and a single pre-compiled generic type handles all parameter counts, reducing generated code and build times.

```csharp
// Before (v0.50.0):
stub.Add.When(1, 2).Return(100);

// After (v0.51.0):
stub.Add.When((1, 2)).Return(100);
```

Single-parameter methods are unchanged: `stub.GetName.When(42).Return("answer")`.

### Interceptor Type Names

Explicit references to arity-based type names (e.g., `MethodInterceptor2<int, int, int>`) will break. The type is now `MethodInterceptor<Func<int, int, int>, (int a, int b), int>`. Most user code uses `var` and is unaffected.
