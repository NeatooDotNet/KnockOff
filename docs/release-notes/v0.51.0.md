# v0.51.0

**Release Date:** 2026-02-16
**Breaking Changes:** Yes

## Summary

Replace 36 arity-based interceptor types with three tiers of pre-compiled interceptors: zero-param (`*Interceptor0`), single-param (`*Interceptor1` with `LastArg`), and multi-param (`*Interceptor` with `LastArgs` named tuple). TSyncDelegate type parameter enables natural lambda parameters on async simplified callbacks.

## What's New

### Three-Tier Interceptor Architecture

The 36 arity-based types (`MethodInterceptor0` through `MethodInterceptor8`, times 4 families) are replaced by 12 types across three tiers:

**Zero-param** (unchanged from v0.50.0):
- `MethodInterceptor0<TReturn>`, `VoidMethodInterceptor0`, `AsyncMethodInterceptor0<TReturn>`, `AsyncVoidMethodInterceptor0`

**Single-param** (new — `LastArg` singular):
- `MethodInterceptor1<TDelegate, TArg, TReturn>`
- `VoidMethodInterceptor1<TDelegate, TArg>`
- `AsyncMethodInterceptor1<TDelegate, TSyncDelegate, TArg, TReturn>`
- `AsyncVoidMethodInterceptor1<TDelegate, TSyncDelegate, TArg>`

**Multi-param** (2+ params — `LastArgs` named tuple):
- `MethodInterceptor<TDelegate, TArgs, TReturn>`
- `VoidMethodInterceptor<TDelegate, TArgs>`
- `AsyncMethodInterceptor<TSyncDelegate, TDelegate, TArgs, TReturn>`
- `AsyncVoidMethodInterceptor<TSyncDelegate, TDelegate, TArgs>`

### LastArg for Single-Param, LastArgs for Multi-Param

Single-parameter methods use `LastArg` (singular). Multi-parameter methods use `LastArgs` (plural) with named ValueTuple fields, reversing the v0.50.0 `Item1`/`Item2` regression:

```csharp
// Single-param: LastArg
var tracking = stub.GetUser.Return((id) => new User { Id = id });
service.GetUser(42);
Assert.Equal(42, tracking.LastArg);

// Multi-param: LastArgs with named fields
var tracking2 = stub.Update.Call((id, name) => { });
service.Update(1, "Alice");
Assert.Equal(1, tracking2.LastArgs!.Value.id);
```

### TSyncDelegate for Async Callbacks

Async interceptors now carry a `TSyncDelegate` type parameter, enabling natural lambda parameters on simplified sync callbacks:

```csharp
// Before (v0.50.0) - args as tuple:
stub.SaveAsync.Call((args) => savedData = args.data);

// After (v0.51.0) - natural params:
stub.SaveAsync.Call((data) => savedData = data);
```

This applies to `.Call()`, `.Return()`, `.ThenCall()`, and `.ThenReturn()` on async interceptors.

### Ref/Out Overload Dispatch Fix

Fixed a generator bug where explicit interface implementation dispatch passed ref/out arguments as a tuple instead of individual parameters with ref/out modifiers. Overload groups containing ref/out members now work correctly.

## Breaking Changes

### When() Tuple Syntax for 2+ Parameters

For methods with 2+ parameters, `When()` now requires tuple syntax (double parentheses). This is because `TArgs` is a ValueTuple, and a single pre-compiled generic type handles all parameter counts, reducing generated code and build times.

```csharp
// Before (v0.50.0):
stub.Add.When(1, 2).Return(100);

// After (v0.51.0):
stub.Add.When((1, 2)).Return(100);
```

Single-parameter methods are unchanged: `stub.GetName.When(42).Return("answer")`.

### LastArgs to LastArg for Single-Param Methods

Single-parameter methods now use `LastArg` (singular) instead of `LastArgs` (plural). This is a clean break — no deprecated alias.

```csharp
// Before (v0.50.0):
tracking.LastArgs   // on single-param method

// After (v0.51.0):
tracking.LastArg    // on single-param method
tracking.LastArgs   // on multi-param method (unchanged)
```

### Interceptor Type Names

Explicit references to arity-based type names (e.g., `MethodInterceptor2<int, int, int>`) will break. Single-param methods now use `MethodInterceptor1<Func<int, int>, int, int>`. Multi-param methods use `MethodInterceptor<Func<int, int, int>, (int a, int b), int>`. Most user code uses `var` and is unaffected.
