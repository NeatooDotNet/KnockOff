# v0.44.0

**Release Date:** 2026-02-08
**Breaking Changes:** No

## Summary

Fixes generator bug that incorrectly added `where T : class` constraint to explicit interface implementations for unconstrained nullable generic methods. Also adds comprehensive test coverage for all common C# generic constraint patterns.

## What's New

### Generic Constraint Bug Fix

The generator was incorrectly adding `where T : class` to explicit interface implementations when:
- The return type was `T?` (nullable type parameter)
- The type parameter had no constraints or only interface constraints

This caused CS8665 compiler errors and blocked Rocks parity for methods like `TData? NullableValues<TData>(TData? data)`.

**Fixed behavior:**
- Unconstrained `T?` methods: No `where T : class` added; nullable annotations stripped; `#nullable disable`/`#nullable restore` pragmas used
- Interface-only constraints (e.g., `where T : IDisposable`): No `where T : class` added
- Class-implying constraints (e.g., `where T : Attribute`): Correctly emits `where T : class`
- Explicit `where T : class` constraints: Preserved as expected

### Generic Constraint Coverage

Added comprehensive test coverage for common C# generic constraint patterns:
- `where T : struct` - Value type constraint
- `where T : notnull` - Non-nullable constraint (C# 8+)
- `where T : class, new()` - Class with parameterless constructor
- `where T : class, IComparable, IConvertible` - Multiple interface constraints
- `where T : IComparable<T>` - Self-referential constraint
- `where T : notnull, IDisposable` - Non-nullable with interface
- `where TResult : TBase` - Type parameter constrained by another type parameter

All patterns tested across both standalone (Pattern 1) and inline (Pattern 5) pipelines.
