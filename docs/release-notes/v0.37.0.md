# v0.37.0 - Unified Event API & Array Parameter Bug Fix

**Release Date:** 2026-02-06
**NuGet:** [KnockOff 0.37.0](https://nuget.org/packages/KnockOff/0.37.0)

## Overview

This release unifies the event interceptor API across all patterns (adding `Raise()` and `HasSubscribers` to inline and class stubs) and fixes a bug where array parameter types produced invalid generated code.

## Breaking Changes

### Event API Naming (Inline & Class Stubs)

Event interceptor properties on inline and class stubs no longer have the `Interceptor` suffix:

```csharp
// Before (0.36.0)
stub.StartedInterceptor.Handler?.Invoke(sender, args);

// After (0.37.0)
stub.Started.Raise(sender, args);
```

The `Handler` property is now private. Use `Raise()` and `HasSubscribers` instead.

## New Features

### Unified Event API Across All Patterns

Event interceptors now provide the same API regardless of pattern:

- **`Raise()`** — type-safe event raising for `EventHandler`, `EventHandler<T>`, `Action`, and `Action<T...>`
- **`HasSubscribers`** — check if any handler is attached
- **Private `_handler`** — backing field no longer publicly exposed

Previously only standalone stubs (Pattern 1) had `Raise()` and `HasSubscribers`. Inline stubs required `Handler?.Invoke()`. Now all patterns work identically.

## Bug Fixes

### Array Parameter Types in Generated Identifiers

`GetTypeSuffix(string)` did not handle `[]` array brackets, embedding them verbatim into generated C# identifiers (e.g., `GetItemsDelegate_string[]_...`). This caused compilation errors when stubbing any interface with array parameter types in method overloads.

Fixed by stripping `[]` suffixes and appending `Array` (e.g., `string[]` becomes `StringArray`). All four string-based copies of `GetTypeSuffix` were patched.

### DevelopmentDependency Flag Removed

Removed the `DevelopmentDependency` property that was causing Visual Studio to exclude KnockOff's analyzer DLL from the build.
