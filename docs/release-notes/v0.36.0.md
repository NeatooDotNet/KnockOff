# v0.36.0 - Delegate Stub Rewrite, Async Consistency & Bug Fixes

**Release Date:** 2026-02-06
**NuGet:** [KnockOff 0.36.0](https://nuget.org/packages/KnockOff/0.36.0)

## Overview

This release rewrites delegate stubs to share the same interceptor infrastructure as all other patterns, verifies async API consistency across all 9 patterns, and fixes 3 bugs in When chain verification and type detection.

## New Features

### Delegate Stub Rewrite

Delegate stubs (pattern 7) now use the shared `MethodInterceptorRenderer`, replacing ~700 lines of delegate-specific rendering code. Delegates gain full feature parity with other patterns:

- Async auto-wrapping (`Returns` without `Task.FromResult`)
- Sequence support (`Returns`, `ThenReturns`, `ThenDefault`)
- Fluent builder chaining
- Proper Strict mode enforcement

### Async Method API Consistency

Verified and tested that the three async APIs work identically across all 9 KnockOff stub patterns:

1. **Returns auto-wrap** — `stub.FetchAsync.Returns("value")` without `Task.FromResult`
2. **Simplified OnCall** — `stub.FetchAsync.OnCall(() => "value")` returns unwrapped
3. **Full delegate OnCall** — `stub.FetchAsync.OnCall(() => Task.FromResult("value"))` for custom async logic

Pattern 7 (delegate) is intentionally different — no auto-wrapping since delegate stubs invoke directly.

## Bug Fixes

### When Chain Verification HEAD Bug

When chains with a single matcher (or repeat-last semantics) always reported verification as incomplete. The HEAD pointer never advanced past the last non-terminal matcher, so `CheckVerification()` incorrectly found unvisited matchers.

### User Method Custom Type Detection

User-defined method overrides with custom types (non-primitive parameters) were not detected. `BuildOverrideSignatureKey` used syntax-based short type names (e.g., `User`) while matching used semantic fully-qualified names (e.g., `Namespace.User`). Now uses `SemanticModel.GetTypeInfo()` to resolve types consistently.

### VerifyAll TotalCallCount

`VerifyAll()` reported 0 total calls when all calls were routed through When chain matchers. When chain matcher call counts are now included in `TotalCallCount` computation across all renderer pipelines.

## Documentation
