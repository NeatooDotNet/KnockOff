# v0.51.2

**Release Date:** 2026-02-16
**Breaking Changes:** No

## Summary

Fix CS9035 compilation error when a stubbed method returns a type with `required` members. The smart default factory now correctly falls back to throwing instead of emitting `new T()`.

## What's Fixed

### CS9035 Required Member Not Set in Smart Default (All Patterns)

When a stubbed method returns a concrete class with `required` properties or fields, the generator emitted `new T()` as the smart default return value. This fails at compile time because required members must be initialized in the object initializer.

```csharp
public class TreatmentGenerationResult
{
    public required ITreatment Treatment { get; init; }
}

public interface ITreatmentGenerationService
{
    TreatmentGenerationResult GenerateTreatment(TreatmentGenerationInput input);
}

// Before this fix: generated code emits new TreatmentGenerationResult()
// which fails with CS9035
[KnockOff<ITreatmentGenerationService>]
public partial class MyTests { }
```

**Root cause:** `SymbolHelpers.GetDefaultValueStrategyWithConcreteType()` checked for a public parameterless constructor but did not check whether the type has `required` members. Types with required members cannot be instantiated with plain `new T()`.

**Fix:** Added `HasRequiredMembers()` check that walks the type hierarchy (including base classes) for `required` properties and fields. Types with required members now get `ThrowException` strategy instead of `NewInstance`, generating `throw new InvalidOperationException(...)` as the default.

**Affected patterns:** All patterns (1-9) -- the fix is in the shared `SymbolHelpers` used by all builder pipelines.

**Files changed:**
- `Models/SymbolHelpers.cs` -- Added `HasRequiredMembers` hierarchy check; gate `NewInstance` on no required members
