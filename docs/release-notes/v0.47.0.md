# v0.47.0

**Release Date:** 2026-02-09
**Breaking Changes:** Yes

## Summary

Major indexer API redesign: per-key builders replace `Backing` dictionary and `OfXxx` patterns, flattened multi-param accessors, predicate-based key matching via `When()`, and per-key verification.

## What's New

### Per-Key Builders (Breaking)

The `Backing` dictionary and `OfXxx` pattern for multi-indexer interfaces have been removed. Indexer configuration now uses per-key builders accessed via C# indexer syntax on the interceptor:

```csharp
// Before (removed):
stub.Indexer.Backing[3] = 42;
stub.Indexer.OfInt32.Get((int key) => key * 10);

// After:
stub.Indexer[3].Returns(42);                      // per-key fixed value
stub.Indexer[3].Get(() => ComputeIt());            // per-key callback
stub.Indexer[3].Returns(1).ThenReturns(2);         // per-key sequence
stub.Indexer.Get((int key) => key * 10);           // all-keys fallback
```

Multi-indexer interfaces use C# overload resolution by key type:

```csharp
// Interface has this[int] and this[string]
stub.Indexer[3].Returns(42);           // int indexer
stub.Indexer["foo"].Returns("bar");    // string indexer
```

**Note:** Per-key builders use `Returns`/`ThenReturns` naming (not `Return`/`ThenReturn`). This is intentional — per-key configuration is declarative, matching Moq/NSubstitute convention.

### Flattened Multi-Param Indexer Accessors (Breaking)

Multi-parameter indexers now use flattened C# indexer syntax instead of tuple keys:

```csharp
// Before (removed):
stub.Indexer[(1, 2)].Returns(3.14);

// After:
stub.Indexer[1, 2].Returns(3.14);
```

Callbacks and library interfaces still use named tuple TKey — only the indexer accessor is flattened.

### Predicate-Based Key Matching (`When`)

Indexers now support `When(predicate)` for matching keys by condition, similar to the existing `When()` API for methods:

```csharp
stub.Indexer.When(key => key.StartsWith("prefix_")).Returns("matched");
stub.Indexer.When(key => key > 100).Set((key, value) => { /* handle */ });
```

When predicates slot into the priority chain above all-keys callbacks but below exact per-key matches.

### Per-Key Verification

Per-key builders now expose `VerifyGet()` and `VerifySet()` for verifying access to specific keys:

```csharp
stub.Indexer["key"].VerifyGet();                   // at least once
stub.Indexer["key"].VerifyGet(Called.Exactly(2));   // exact count
stub.Indexer["key"].VerifySet();
stub.Indexer["key"].VerifySet(Called.Once);
```

### Priority Chain

The indexer getter/setter resolution priority is:

1. Per-key exact match (`stub.Indexer[key].Returns(...)`)
2. When predicate match (`stub.Indexer.When(pred).Returns(...)`)
3. All-keys sequence (if active)
4. All-keys callback (`stub.Indexer.Get(...)`)
5. Source delegation
6. Strict mode / default

## Migration Guide

| Before (v0.46.0) | After (v0.47.0) |
|---|---|
| `stub.Indexer.Backing[key] = value` | `stub.Indexer[key].Returns(value)` |
| `stub.Indexer.OfInt32.Get(cb)` | `stub.Indexer.Get((int key) => ...)` |
| `stub.Indexer.OfString.Get(cb)` | `stub.Indexer.Get((string key) => ...)` |
| `stub.Indexer[(1, 2)].Returns(v)` | `stub.Indexer[1, 2].Returns(v)` |
