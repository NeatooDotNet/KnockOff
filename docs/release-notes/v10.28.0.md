# v10.28.0 - Simplified Async Callbacks

**Release Date:** 2026-01-26
**NuGet:** [KnockOff 10.28.0](https://nuget.org/packages/KnockOff/10.28.0)

## Overview

This release adds simplified callback overloads for async methods, eliminating verbose `Task.FromResult()` and `Task.CompletedTask` wrapping in unit tests.

## What's New

### Simplified Callbacks for `Task<T>` / `ValueTask<T>` Methods

New `OnCall(Func<TParams..., TInnerType>)` overload that auto-wraps the result:

```csharp
// Before (verbose)
stub.GetUserAsync.OnCall((id) => Task.FromResult(user));
stub.GetCachedValueAsync.OnCall((key) => new ValueTask<string>(cachedValue));

// After (simplified)
stub.GetUserAsync.OnCall((id) => user);
stub.GetCachedValueAsync.OnCall((key) => cachedValue);
```

### Simplified Callbacks for Void Async Methods (`Task` / `ValueTask`)

New `OnCall(Action<TParams...>)` overload that auto-returns `Task.CompletedTask` or `default(ValueTask)`:

```csharp
// Before (verbose)
stub.SaveUserAsync.OnCall((user) => { ValidateUser(user); return Task.CompletedTask; });
stub.LogAsync.OnCall((msg) => { Console.WriteLine(msg); return default(ValueTask); });

// After (simplified)
stub.SaveUserAsync.OnCall((user) => ValidateUser(user));
stub.LogAsync.OnCall((msg) => Console.WriteLine(msg));
```

### When to Use Each Pattern

| Scenario | Recommended API |
|----------|-----------------|
| Static return value | `OnCall(value)` |
| Computed value per call | `OnCall((params) => computedValue)` |
| Actual async operation | `OnCall((params) => Task.FromResult(...))` or `OnCall(async (params) => ...)` |

## Breaking Changes

None. This is a purely additive feature.

## Technical Notes

- C# correctly resolves between `Func<T, Task<U>>` and `Func<T, U>` based on the lambda return type
- C# correctly resolves between `Func<T, Task>` and `Action<T>` based on whether the lambda body returns void
- All three patterns (Standalone, Inline Interface, Inline Class) are supported
- Full tracking support (CallCount, LastArg, LastArgs, Verify)

## Edge Case: Throw-Only Lambdas

Lambdas that only throw create ambiguity because `throw` expressions have no return type:

```csharp
// Ambiguous - use explicit delegate type
stub.GetUserAsync.OnCall((Func<int, Task<User?>>)((id) => throw new NotFoundException()));
```

A future release may add a dedicated `.Throws()` API for this scenario.
