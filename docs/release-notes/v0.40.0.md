# v0.40.0

**Release Date:** 2026-02-07
**Breaking Changes:** No

## Summary

Bug fixes for class stub generation: missing `new` keyword on object-override interceptors (CS0108) and missing `using System.Linq;` in generated code (CS1061). Also documents the "last one wins" configuration principle.

## Bug Fixes

### Fix: Missing `new` keyword on class stub interceptors (CS0108)

When stubbing abstract classes that override `Equals`, `GetHashCode`, or `ToString`, the generated interceptor properties were missing the `new` keyword, causing CS0108 compiler errors with `TreatWarningsAsErrors`.

**Affected patterns:** All class stub patterns (3, 4, 6, 9)

**Fixed files:**
- `ClassModelBuilder.cs` / `StandaloneClassModelBuilder.cs` — compute `NeedsNewKeyword` (was hardcoded `false`)
- `ClassRenderer.cs` / `StandaloneClassRenderer.cs` — emit `new` keyword when needed

### Fix: Missing `using System.Linq;` in generated code (CS1061)

Overloaded method stubs generate `.Sum()` for `TotalCallCount` but only emitted `using System.Linq;` conditionally (when generic methods present). Projects without `ImplicitUsings` would get CS1061 errors.

**Fixed files:**
- `InlineRenderer.cs` / `FlatRenderer.cs` — changed from conditional to unconditional
- `StandaloneClassRenderer.cs` — added missing `using System.Linq;` emission

## Documentation

- Documented "last one wins" as an overall configuration principle for Return, Call, Get, Set, and When
- Added known bug note: When() entry point currently accumulates like ThenWhen() instead of replacing
