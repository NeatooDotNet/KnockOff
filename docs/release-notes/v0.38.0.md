# v0.38.0 - Unified Method Configuration API

**Release Date:** 2026-02-07
**NuGet:** [KnockOff 0.38.0](https://nuget.org/packages/KnockOff/0.38.0)

## Overview

This release unifies the method configuration API by replacing `.OnCall()` with `.Returns()` for non-void methods and `.Execute()` for void methods. Sequence chaining is renamed from `.ThenCall()` to `.ThenReturns()`/`.ThenExecute()`. Void When chains use `.Execute()`/`.ThenExecute()` instead of `.Call()`/`.ThenCall()`. Simplified async `ThenReturns` overloads are added for `Task<T>` and `ValueTask<T>` sequences.

## Breaking Changes

### `.OnCall()` Removed

`.OnCall(callback)` no longer exists on method interceptors. Replace with:

- **Non-void methods:** `.Returns(callback)`
- **Void methods:** `.Execute(callback)`

```csharp
// Before (0.37.0)
stub.GetName.OnCall((id) => "Alice");
stub.DoWork.OnCall(() => { log.Add("called"); });

// After (0.38.0)
stub.GetName.Returns((id) => "Alice");
stub.DoWork.Execute(() => { log.Add("called"); });
```

### `.ThenCall()` Renamed on Sequences

Sequence chaining uses `.ThenReturns()` for non-void and `.ThenExecute()` for void:

```csharp
// Before (0.37.0)
stub.GetName.OnCall(cb1).ThenCall(cb2);
stub.DoWork.OnCall(cb1).ThenCall(cb2);

// After (0.38.0)
stub.GetName.Returns(cb1).ThenReturns(cb2);
stub.DoWork.Execute(cb1).ThenExecute(cb2);
```

### Void When Chain `.Call()`/`.ThenCall()` Renamed

Void When chain terminal methods renamed to `.Execute()`/`.ThenExecute()`:

```csharp
// Before (0.37.0)
stub.DoWork.When(param).Call(() => { });
stub.DoWork.When(param).Call(cb1).ThenCall(cb2);

// After (0.38.0)
stub.DoWork.When(param).Execute(() => { });
stub.DoWork.When(param).Execute(cb1).ThenExecute(cb2);
```

**Note:** Non-void When chain `.ThenCall()` is unchanged (different semantics from sequence chaining).

## New Features

### Simplified Async `ThenReturns` Overloads

For `Task<T>` and `ValueTask<T>` methods, `ThenReturns` now accepts simplified callbacks that return `T` instead of `Task<T>`:

```csharp
// Before: required full delegate match
stub.GetDataAsync.OnCall((id) => Task.FromResult("v1"))
    .ThenCall((id) => Task.FromResult("v2"));

// After: simplified callbacks auto-wrapped
stub.GetDataAsync.Returns((id) => "v1")
    .ThenReturns((id) => "v2");
```

### Void/Non-Void Type Safety

Generated interceptors now only expose the correct API:
- Non-void methods: `IMethodReturnsBuilder` with `.ThenReturns()`
- Void methods: `IMethodExecuteBuilder` with `.ThenExecute()`

The wrong method does not exist at compile time.

## Migration

This is a mechanical rename:

| Before | After |
|--------|-------|
| `.OnCall(callback)` (non-void) | `.Returns(callback)` |
| `.OnCall(callback)` (void) | `.Execute(callback)` |
| `.ThenCall(callback)` (non-void sequence) | `.ThenReturns(callback)` |
| `.ThenCall(callback)` (void sequence) | `.ThenExecute(callback)` |
| `.Call(callback)` (void When chain) | `.Execute(callback)` |
| `.ThenCall(callback)` (void When chain) | `.ThenExecute(callback)` |

**Tip:** Build your project after upgrading. Every rename produces a clear compiler error showing the affected call site.
