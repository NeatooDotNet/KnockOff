# KnockOff v10.24.0

**Release Date:** 2026-01-20
**Breaking Changes:** Yes

---

## Summary

Removes `CallCount` and `TotalCallCount` from public method interceptor APIs to simplify the API surface and guide users toward idiomatic verification patterns.

---

## What's New

### Breaking: Removed CallCount from Public API

`CallCount` and `TotalCallCount` properties have been removed from public method interceptor APIs. These properties encouraged low-level assertions instead of the more expressive verification API.

**Removed APIs:**
- `IMethodTracking.CallCount` interface property
- `IMethodSequence.TotalCallCount` interface property
- Generated method interceptor `CallCount` properties
- Generated generic method handler `TotalCallCount` properties

**Before:**

```csharp
var stub = new UserRepositoryStub();
stub.GetById(1);
stub.GetById(2);

// Low-level assertion using CallCount
Assert.Equal(2, stub.GetById.CallCount);

// Generic method call count
stub.GenericMethod<string>();
Assert.Equal(1, stub.GenericMethod.TotalCallCount);
```

**After:**

```csharp
var stub = new UserRepositoryStub();
stub.GetById(1);
stub.GetById(2);

// Idiomatic verification using Times API
stub.GetById.Verify(Times.Exactly(2));

// Or verify at least once (default)
stub.GetById.Verify();

// Generic method verification
stub.GenericMethod<string>();
stub.GenericMethod.Verify(Times.Once);
```

**What Remains Unchanged:**

Property, indexer, and event interceptors use different tracking semantics and are **not affected**:
- Property interceptors: `GetCount` / `SetCount` remain (separate get/set tracking)
- Indexer interceptors: `GetCount` / `SetCount` remain (separate get/set tracking)
- Event interceptors: `AddCount` / `RemoveCount` remain (subscribe/unsubscribe tracking)

## Migration Guide

Update assertions to use the verification API:

| Old Pattern | New Pattern |
|-------------|-------------|
| `Assert.Equal(1, stub.Method.CallCount)` | `stub.Method.Verify(Times.Once)` |
| `Assert.Equal(n, stub.Method.CallCount)` | `stub.Method.Verify(Times.Exactly(n))` |
| `Assert.Equal(0, stub.Method.CallCount)` | `stub.Method.Verify(Times.Never)` |
| `stub.Method.CallCount > 0` | `stub.Method.Verify()` |
| `Assert.True(stub.Method.CallCount >= 2)` | `stub.Method.Verify(Times.AtLeast(2))` |
| `stub.GenericMethod.TotalCallCount` | `stub.GenericMethod.Verify(Times.AtLeast(1))` |
| `stub.GenericMethod.Of<T>().CallCount` | `stub.GenericMethod.Of<T>().Verify(Times.Exactly(n))` |

**Examples:**

```csharp
// Before
if (stub.Connect.CallCount > 0)
{
    // Connection was established
}

// After - verification throws if not called
stub.Connect.Verify();
// Connection was established (or exception thrown)
```

```csharp
// Before
Assert.Equal(3, stub.Process.CallCount);

// After
stub.Process.Verify(Times.Exactly(3));
```

## Technical Details

CallCount tracking has been changed from public to internal visibility:

**Interfaces Modified:**
- `IMethodSequence.cs` - Removed `TotalCallCount` property
- `IMethodTracking.cs` - Removed `CallCount` property

**Generator Changes:**
- `MethodInterceptorRenderer.cs` - Changed `CallCount` to internal
- `FlatRenderer.cs` - Changed `TotalCallCount` and `CallCount` to internal
- `InlineRenderer.cs` - Changed `TotalCallCount` to internal
- `ClassRenderer.cs` - Changed `CallCount` to internal

Internal call tracking remains functional to support:
- `Verify(Times)` API implementation
- Sequence tracking and verification
