# v0.52.0

**Release Date:** 2026-02-18
**Breaking Changes:** Yes

## Summary

Comprehensive IntelliSense API redesign. Fully generated interceptor classes replace precompiled generic types, eliminating generic type noise from tooltips. Unified `Call`/`Return` API with named tuples for multi-parameter callbacks. XML comments on all generated methods. Single property for overloaded methods with tracking handles for per-overload verification.

## What's New

### Fully Generated Interceptor Classes

All method interceptors are now fully generated classes inheriting from a non-generic `MethodInterceptorRuntime` base. No generic type parameters leak into IntelliSense tooltips. Users see clean method signatures instead of `AsyncVoidMethodInterceptor<TDelegate, TSyncDelegate, TArgs>`.

### Unified Call/Return API

- `Call(callback)` / `ThenCall(callback)` -- unified callback registration for both void and non-void methods
- `Return(value)` / `ThenReturn(value)` -- value-only, never accepts lambdas/delegates
- Mixing allowed in sequences: `Return("A").ThenCall(args => Compute(args.id))`

### Named Tuples for 2+ Parameter Callbacks

Methods with 2+ parameters use named ValueTuples in callback signatures. IntelliSense shows parameter names directly:

```csharp
// IntelliSense shows: Action<(int id, string name)>
stub.Update.Call(args => Save(args.id, args.name));

// When chains also use tuples:
stub.Add.When(args => args.a > 0).Return(42);
```

Single-parameter methods use raw types (no tuple wrapping). Zero-parameter methods use parameterless delegates.

### XML Comments on All Generated Methods

Every generated `Call`, `Return`, `When`, and `ThenCall`/`ThenReturn` method includes XML documentation:
- Class-level summary shows the method signature: `/// <summary>Tracks and configures behavior for Add(int a, int b).</summary>`
- `Call` summary: `/// <summary>Configures callback for Add(int a, int b).</summary>`
- `Return` summary: `/// <summary>Sets return value for Add(int a, int b).</summary>`
- `When` summary: `/// <summary>Configures parameter matching for Add(int a, int b).</summary>`
- User-defined XML `<param>` documentation is migrated from the original interface/class

### Single Property for Overloaded Methods

Overloaded methods share a single interceptor property. No more numbered slots (`Process`, `Process2`, `Process3`). Call/Return overloads disambiguate by parameter types in the lambda:

```csharp
// Both overloads through single property:
stub.Process.Call((int x) => HandleInt(x));
stub.Process.Call((string s) => HandleString(s));
```

### Tracking Handles for Per-Overload Verification

`Call` and `Return` return tracking handles that support `Verify()`, `LastArg`/`LastArgs`, and `Reset()`:

```csharp
var tracking = stub.Process.Call((int x) => x * 2);
service.Process(42);
tracking.Verify();
Assert.Equal(42, tracking.LastArg);
```

## Breaking Changes

### API Name Changes

| Before | After |
|--------|-------|
| `Returns(callback)` | `Call(callback)` |
| `Returns(value)` | `Return(value)` |
| `Execute(callback)` | `Call(callback)` |
| `OnCall(callback)` | `Call(callback)` |
| `ThenReturns(callback)` | `ThenCall(callback)` |
| `ThenReturns(value)` | `ThenReturn(value)` |
| `ThenExecute(callback)` | `ThenCall(callback)` |
| `Of<T>().Return(callback)` | `Of<T>().Call(callback)` |

### Tuple Callbacks for 2+ Parameters

Methods with 2+ parameters now receive a named tuple instead of individual parameters:

```csharp
// Before:
stub.Add.Returns((a, b) => a + b);

// After:
stub.Add.Call(args => args.a + args.b);
```

### When() Tuple Syntax for 2+ Parameters

```csharp
// Before:
stub.Add.When(1, 2).Returns(100);

// After:
stub.Add.When((1, 2)).Return(100);
```

Single-parameter `When` is unchanged: `stub.GetName.When(42).Return("answer")`.

### Interceptor Type Changes

Explicit references to precompiled interceptor type names will break. Most user code uses `var` and is unaffected. The 12 precompiled sealed types, 2 base classes, and 8 slot system files have been removed.

## Removed

### 12 Precompiled Interceptor Sealed Types

- `MethodInterceptor`, `MethodInterceptor0`, `MethodInterceptor1`
- `VoidMethodInterceptor`, `VoidMethodInterceptor0`, `VoidMethodInterceptor1`
- `AsyncMethodInterceptor`, `AsyncMethodInterceptor0`, `AsyncMethodInterceptor1`
- `AsyncVoidMethodInterceptor`, `AsyncVoidMethodInterceptor0`, `AsyncVoidMethodInterceptor1`

### Base Class Hierarchy

- `VoidMethodInterceptorBase<TDelegate, TArgs>`
- `MethodInterceptorBase<TDelegate, TArgs, TReturn>`

### Slot System (8 files)

- `IMethodOverloadSlots`, `IAsyncMethodOverloadSlots`, `IVoidOverloadSlots`, `IAsyncVoidOverloadSlots`
- `MethodSlotExtensions`, `AsyncMethodSlotExtensions`, `VoidSlotExtensions`, `AsyncVoidSlotExtensions`

### DelegateInvokerFactory

- `DelegateInvokerFactory` -- expression tree delegate invoker used only by removed precompiled types
