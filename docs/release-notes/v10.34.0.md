# v10.34.0 - Standalone Class Stubs & Sequence Improvements

**Release Date:** 2026-02-04
**NuGet:** [KnockOff 10.34.0](https://nuget.org/packages/KnockOff/10.34.0)

## Overview

This release adds two new stub patterns for stubbing classes with virtual/abstract members, introduces NSubstitute-style params syntax for sequences, and adds OnCall/Returns support to user-defined methods. KnockOff now supports **9 stub patterns** (up from 7).

## Breaking Changes

### Sequence Exhaustion Behavior

Sequences now repeat the last value after exhaustion instead of returning `default(T)`. This matches NSubstitute's behavior.

**Before:**
```csharp
stub.GetNext.Returns(1).ThenReturns(2);
stub.GetNext();  // 1
stub.GetNext();  // 2
stub.GetNext();  // 0 (default)
```

**After:**
```csharp
stub.GetNext.Returns(1).ThenReturns(2);
stub.GetNext();  // 1
stub.GetNext();  // 2
stub.GetNext();  // 2 (repeats last)
```

**Migration:** Use `ThenDefault()` to explicitly return `default(T)` after exhaustion:
```csharp
stub.GetNext.Returns(1).ThenReturns(2).ThenDefault();
```

## New Features

### Standalone Class Stubs (Patterns 3 & 4)

Two new patterns for stubbing classes with virtual/abstract members in separate files:

**Pattern 3 - Standalone Class:**
```csharp
[KnockOffBase<MyService>]
public partial class MyServiceStub { }

// Usage
var stub = new MyServiceStub();
stub.Calculate.Returns(42);
var service = stub.Object;  // Access the class instance
```

**Pattern 4 - Generic Standalone Class:**
```csharp
[KnockOffBase(typeof(Repository<>))]
public partial class RepositoryStub<T> { }

// Usage
var stub = new RepositoryStub<Customer>();
stub.GetById.Returns(new Customer());
var repo = stub.Object;
```

Both patterns use composition (wrapper + nested Impl class) matching inline class stubs. Access the actual class instance via the `.Object` property.

### Params Sequence Overloads

NSubstitute-style syntax for creating value sequences:

```csharp
// Multiple values in single call
stub.GetNext.Returns(1, 2, 3);  // Returns 1, then 2, then 3 (repeats 3)

// Extending sequences
stub.GetPrice.Returns(10.0m).ThenReturns(20.0m, 30.0m, 40.0m);
```

Async methods auto-wrap values without `Task.FromResult`:
```csharp
stub.FetchAsync.Returns("first", "second");  // No wrapping needed
```

### ThenDefault() for Sequence Exhaustion

Explicitly return `default(T)` after sequence exhaustion:

```csharp
stub.GetName.Returns("first").ThenReturns("second").ThenDefault();
stub.GetName();  // "first"
stub.GetName();  // "second"
stub.GetName();  // null (explicit default)
```

### OnCall/Returns for User-Defined Methods

User methods now support per-test overrides via `OnCall()` and `Returns()`:

```csharp
public partial class MyStub : ICalculator
{
    // User-defined default implementation
    protected override int Calculate_(int x) => x * 2;
}

// Test can override the default
var stub = new MyStub();
stub.Calculate.Returns(100);  // Overrides user method
Assert.Equal(100, stub.Calculate(5));

// Or use callback
stub.Calculate.OnCall(x => x * 3);
```

Priority chain: OnCall > User Override > Strict > Default

### Base Class Pattern for User Methods

User-defined methods now use a base class pattern for compile-time safety:

```csharp
// Generator creates: public abstract partial class MyStubBase
// with protected virtual methods like: protected virtual int Calculate_(int x)

[KnockOff]
public partial class MyStub : ICalculator
{
    // Override with underscore suffix for type safety
    protected override int Calculate_(int x) => x * 2;
}
```

Benefits:
- Compile-time errors if method signature changes
- Clean interceptor names (no numbered suffixes)
- IDE auto-complete for available methods

### Unified Class Stub Overload API

Class stubs now use single interceptors with multiple `OnCall` overloads, matching interface stub behavior:

**Before:**
```csharp
stub.Transform1.OnCall((int v) => v.ToString());
stub.Transform2.OnCall((string s) => s.ToUpper());
```

**After:**
```csharp
stub.Transform.OnCall((int v) => v.ToString());
stub.Transform.OnCall((string s) => s.ToUpper());
```

## Refactoring

### CallCount Removed from Public API

The `CallCount` property has been replaced with an internal `_callCount` field. Tests should use the `Verify()` API instead:

**Before:**
```csharp
Assert.Equal(2, stub.Calculate.CallCount);
```

**After:**
```csharp
stub.Calculate.Verify(Times.Exactly(2));
```

## Technical Notes

- Added `KnockOffBaseAttribute<T>` and `KnockOffBaseAttribute` for standalone class stubs
- Added `StandaloneClassModelBuilder` and `StandaloneClassRenderer`
- Added `ThenDefault()` to `IMethodSequence`, `IPropertySequence`, `IIndexerSequence`
- Added `KO0200` diagnostic for user-defined base class naming conflicts
- 100+ new tests covering all new features
