# v0.42.0

**Release Date:** 2026-02-08
**Breaking Changes:** Yes

## Summary

Task/ValueTask methods (without `<T>`) previously generated both `Return(delegate)` and `Call(Action<...>)` entry points. The duplicate `Call` overload has been renamed to `Return` so all non-void methods consistently use `Return` as their entry point.

## Breaking Changes

### `Call(Action<...>)` renamed to `Return(Action<...>)` on Task/ValueTask methods

Methods returning `Task` or `ValueTask` (without `<T>`) previously generated a simplified void callback named `Call(Action<...>)`. This has been renamed to `Return(Action<...>)` for consistency with all other non-void method entry points.

**Before:**
```csharp
stub.SaveAsync.Return(() => Task.CompletedTask);  // full delegate
stub.SaveAsync.Call(() => { });                   // simplified void callback
```

**After:**
```csharp
stub.SaveAsync.Return(() => Task.CompletedTask);  // full delegate
stub.SaveAsync.Return(() => { });                 // simplified void callback
```

**Migration:** Replace `.Call(` with `.Return(` on Task/ValueTask method configurations. The compiler will guide you — `Call` will no longer exist on these interceptors.

**Not affected:** `Call()` on truly void methods (`void` return type) is unchanged.
