# v0.54.0

**Release Date:** 2026-02-19
**Breaking Changes:** No

## Summary

Bug fix: stub overrides on a subset of overloaded methods no longer split the interceptor group into separate properties.

## What's Fixed

### Stub Override Partial Overload Split Bug

When a user provided a stub override for only some overloads of a method (e.g., `Format_(string input)` when `Format` has 3 overloads), the generator incorrectly split the overload group into separate interceptors (`stub.Format` and `stub.Format2`). This broke delegate generation, overload numbering, and tracking handles.

**Before (broken):**
```csharp
// Generator created two interceptors
stub.Format      // only Format(string) — with stub override
stub.Format2     // Format(string, bool) and Format(string, bool, int) — separate
```

**After (fixed):**
```csharp
// Single interceptor with all overloads, per-signature stub override
stub.Format      // all 3 overloads, stub override on Format(string) only
stub.Format.Call((string input, bool uppercase) => ...);  // disambiguates correctly
```
