# v0.53.0

**Release Date:** 2026-02-19
**Breaking Changes:** Yes

## Summary

Custom named delegates replace `Func<tuple>`/`Action<tuple>` for all Call callbacks and When predicates. Fixes CS0121 overload ambiguity for interfaces with same-type overloads. Method-name-based generated type names (`AddDelegate`, `AddImpl`, `AddSequence`). XML doc summaries now include return types.

## What's New

### Custom Named Delegates for Call Callbacks

Every method now generates a dedicated delegate type with full parameter names. IntelliSense shows the original method signature directly in the delegate tooltip:

```csharp
// Before (v0.52.0): tuple-based Func
stub.Add.Call(args => args.a + args.b);

// After: custom delegate with named params
stub.Add.Call((int a, int b) => a + b);
```

### CS0121 Overload Ambiguity Fix

Interfaces with overloaded methods sharing the same parameter types but different arities no longer cause CS0121:

```csharp
public interface IAuthSvc
{
    bool ValidateCredentials(string username, string password);
    bool ValidateCredentials(string username, string password, string token);
}

// Now works -- each overload has a unique delegate type:
stub.ValidateCredentials.Call((string username, string password) => true);
stub.ValidateCredentials.Call((string username, string password, string token) => true);
```

### Custom Predicate Delegates for When Chains

When predicates also use custom delegates for consistency and to avoid the same CS0121 issue:

```csharp
// Before: tuple-based Func predicate
stub.Add.When(args => args.a > 0).Return(42);

// After: custom predicate delegate
stub.Add.When((int a, int b) => a > 0).Return(42);
```

When exact-match is unchanged: `stub.Add.When(1, 2).Return(100)`.

### Method-Name-Based Generated Type Names

Generated types use the method name instead of generic names:

| Before (v0.52.0) | After |
|-------------------|-------|
| `MethodCallBuilderImpl` | `AddImpl` |
| `MethodSequenceImpl` | `AddSequence` |
| `Func<(int a, int b), int>` | `AddDelegate` |

Overloaded methods use numbered suffixes: `FormatDelegate`, `FormatDelegate2`, `FormatDelegate3`.

### XML Doc Return Types

XML doc summaries now include the return type for non-void methods:

```csharp
/// <summary>Configures callback for Add(int a, int b) -> int.</summary>
public AddImpl Call(AddDelegate callback)
```

### Simplified Async Delegate Naming

Async methods with simplified (unwrapped) callbacks use `{MethodName}SyncDelegate`:

```csharp
/// <summary>Callback delegate for GetDataAsync(int id) -> string.
/// Result auto-wrapped in Task.FromResult.</summary>
public delegate string GetDataAsyncSyncDelegate(int id);
```

## Breaking Changes

### Callback Syntax for 2+ Parameters

Tuple accessor syntax replaced with direct delegate parameters:

```csharp
// Before:
stub.Add.Call(args => args.a + args.b);

// After:
stub.Add.Call((int a, int b) => a + b);
```

### When Predicate Syntax for 2+ Parameters

```csharp
// Before:
stub.Add.When(args => args.a > 0).Return(42);

// After:
stub.Add.When((int a, int b) => a > 0).Return(42);
```

### Generated Type Name Changes

| Before | After |
|--------|-------|
| `MethodCallBuilderImpl` | `{MethodName}Impl` |
| `MethodSequenceImpl` | `{MethodName}Sequence` |
| `Func<(T1, T2), TReturn>` | `{MethodName}Delegate` |
| `Func<(T1, T2), bool>` (When) | `{MethodName}Predicate` |

### Dead Code Removed

- `RenderSingleSignatureContent` (~348 lines of dead renderer code from v0.52.0)
