# v0.51.1

**Release Date:** 2026-02-16
**Breaking Changes:** No

## Summary

Fix CS0102 duplicate delegate type definitions when multiple inline stubs share a base interface with overloaded methods.

## What's Fixed

### CS0102 Duplicate Compositor Delegate Types (Inline Pattern)

When a test class uses multiple `[KnockOff<T>]` attributes for interfaces that share a common base interface with overloaded methods, the generator emitted duplicate delegate type declarations at the `Stubs` scope, causing CS0102 compilation errors.

```csharp
public interface IEntityBase
{
    Task WaitForTasks();
    Task WaitForTasks(CancellationToken token);  // overload
}

public interface IEmployee : IEntityBase { string Name { get; set; } }
public interface IDepartment : IEntityBase { string Title { get; set; } }

// Before this fix: CS0102 - duplicate 'WaitForTasksDelegate_...' in Stubs
[KnockOff<IEmployee>]
[KnockOff<IDepartment>]
public partial class MyTests { }
```

**Root cause:** Overload compositor delegate declarations are emitted outside individual stub classes (at the `Stubs` level) so they can be referenced in compositor class base type lists. When multiple stubs inherited the same overloaded methods, the delegate names collided because they don't include a stub-specific prefix.

**Fix:** Added deduplication tracking across all stubs within a generated file. Identical delegate declarations from shared base interfaces are emitted once.

**Affected patterns:** 5 (Inline Interface), 6 (Inline Class) -- only when multiple stubs share a base type with overloaded methods in the same test class.

**Files changed:**
- `Renderer/Shared/PreCompiledInterceptorRenderer.cs` -- Added optional `emittedDelegates` parameter to `RenderOverloadCompositorClass` for cross-stub deduplication
- `Renderer/InlineRenderer.cs` -- Creates shared `HashSet<string>` passed through all stub rendering calls
- `Renderer/ClassRenderer.cs` -- Accepts and passes through the deduplication set
