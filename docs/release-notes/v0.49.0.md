# v0.49.0

**Release Date:** 2026-02-13
**Breaking Changes:** No

## Summary

Reduce generated code size by eliminating thin inner subclasses from base-class-mode interceptors. Base class inner classes now implement library interfaces directly. Also fixes a bug where `Verifiable(Called times)` silently discarded the `times` parameter on property and indexer builders.

## What's New

### Generated Code Size Reduction

Interceptor base classes (introduced in v0.48.0's internal architecture) contained inner classes (`PropertyGetBuilderBase`, `PropertyGetSequenceBase`, etc.) that required generated thin subclasses to bridge between base class methods and library interfaces. These thin subclasses are now eliminated:

- **Property interceptors:** All 4 builder/sequence thin subclasses eliminated (100%). Generated `new Get()` / `new Set()` methods also removed.
- **Indexer interceptors:** All 7 builder/sequence/When-chain thin subclasses eliminated (100%).
- **Method interceptors:** Sequence thin subclasses eliminated. Builder and When chain inner classes remain generated (required for `LastArg`/`LastArgs` tracking and parameter-specific `ThenWhen`/`Call` overloads).

Estimated ~19% further reduction in generated code size on top of the previous base class work.

## What's Fixed

### `Verifiable(Called times)` Silently Discards Times Parameter

The explicit interface implementation for `IPropertyGetTracking.Verifiable(Called times)`, `IPropertySetTracking<T>.Verifiable(Called times)`, `IIndexerGetTracking<TKey>.Verifiable(Called times)`, and `IIndexerSetTracking<TKey, TValue>.Verifiable(Called times)` delegated to the parameterless `Verifiable()`, silently discarding the `Called` constraint. This meant `stub.Name.Get(() => "test").Verifiable(Called.Exactly(3))` actually used `Called.AtLeastOnce`.

Fixed in both base-class-mode (via base class implementation) and inline-mode (via renderer fix).
