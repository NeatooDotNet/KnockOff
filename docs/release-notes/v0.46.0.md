# v0.46.0

**Release Date:** 2026-02-09
**Breaking Changes:** No

## Summary

Fixes 7 generator bugs across indexers and generic types, adds multi-parameter indexer support, init-only indexer support, and multi-arity generic method support (`Of<T1, T2>()`).

## What's New

### Multi-Parameter Indexer Support

Interfaces with multi-parameter indexers (`this[int a, string b]`) now generate correct stubs across all patterns. The key type is a named ValueTuple (e.g., `(int a, string b)`), used consistently in `Get()`, `Set()`, `ThenGet()`, `ThenSet()`, and `Backing` dictionary APIs.

```csharp
stub.Indexer.Get(key => key.a + key.b.Length);
stub.Indexer.Backing[(3, "b")] = 42;
```

Supports any number of parameters (2, 3, 4+) — the logic is fully generic.

**Known limitation:** Params array indexers (`this[int a, params string[] b]`) work with `Get()` callbacks but not with `Backing` dictionaries due to array reference equality.

### Init-Only Indexer Support

Interfaces with `init` accessors on indexers (`this[int a] { get; init; }` and `this[int a] { init; }`) now generate correct code. The generator emits `init` instead of `set` where required.

### Multi-Arity Generic Methods

Generic methods with 2+ type parameters now work via `Of<T1, T2>()`. Previously only `Of<T>()` (single type parameter) was supported.

```csharp
stub.Convert.Of<int, string>().Return(input => input.ToString());
```

When an interceptor has overloads with different type parameter counts, each arity gets its own `Of<>()` method and typed handler class.

### Generic Method `ref`/`out`/`in` Parameter Fix

Generic methods with `ref`, `out`, or `in` parameters in inline and class patterns now generate correct delegate signatures. The ref kind modifiers are preserved in delegate parameter formatting.

### Indexer `in` Parameter Fix

Indexer parameters with `in` modifier (`this[in int key]`) are now preserved across all 4 pipelines. Previously the `in` modifier was stripped, causing CS0535/CS0539 compilation errors.

### SmartDefault Type Parameter Collision Fix

Generic stubs (patterns 2 and 8) with interfaces containing generic methods no longer produce CS0693 warnings. Internal `SmartDefault<T>` was renamed to avoid type parameter name collisions.

## Bug Summary

| # | Bug | Patterns Affected | Error |
|---|-----|-------------------|-------|
| 1 | Multi-param indexers: standalone only generates first parameter | P1, P2 | CS0539, CS0535 |
| 2 | Multi-param indexers: ThenGet/ThenSet signature mismatch | P5, P6, P8, P9 | CS0535 |
| 3 | Init-only indexer setters emit `set` instead of `init` | All patterns | CS8855 |
| 4 | `in` modifier stripped from indexer parameters | All patterns | CS0535, CS0539 |
| 5 | Generic methods with `out`/`ref` params missing RefKind in delegates | P3, P4, P5, P6, P8, P9 | CS1615 |
| 6 | Generic methods with 2+ type params not supported | All patterns | CS0246, CS0305 |
| 7 | SmartDefault\<T\> type parameter collision in generic stubs | P2, P8 | CS0693 |
